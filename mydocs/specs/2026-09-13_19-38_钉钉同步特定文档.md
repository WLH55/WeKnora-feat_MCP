## 1. Requirements (Context)
- **Goal**: 用户能把"某一篇特定钉钉文档"纳入同步范围——典型场景:文档在「我的文档」或「团队文件」里,不在任何知识库中,现有 wiki 树选择器够不着。
- **In-Scope**:
  - 用户以某种入口(待定,Q1)指定文档,连接器按 dentryUuid 拉取块元素并渲染 Markdown 入库,复用现有 pipeline。
  - 与现有知识库树选择共存(同一数据源里混选知识库 + 单篇文档,或分开,待 Q1)。
  - 增量更新与删除语义(待 Q2/Q3)。
- **Out-of-Scope**:
  - 云盘(Drive)空间浏览连接器(列出「我的文档」「团队文件」整棵树)——用户本轮未要求,仅要求"特定某个文档"。
  - 群空间(spaceType=group)——用户明确「先不用做」。
  - 上传的普通文件(pdf/docx 等)下载——仍走 v1 跳过策略。
  - 钉钉侧写操作。
- **Acceptance Criteria**:
  - [ ] AC1: 用户将一篇位于「我的文档」的在线文档 URL 纳入同步范围后,手动同步能在 WeKnora 知识库中看到该文档(标题、正文、来源标签"钉钉")。
  - [ ] AC2: 该文档在钉钉侧被编辑后,再次同步能更新 WeKnora 中的内容(增量语义按 Q2 决议)。
  - [ ] AC3: 单元测试覆盖 URL→dentryUuid 解析、resource_id 新格式编解码、bare-doc 同步路径(walk 分支)。
  - [ ] AC4: 不引入新的第三方依赖;dingtalk 包测试在 Linux 容器通过。
  - [ ] AC5: 现有知识库树同步行为无回归(现有测试全绿)。

## 2. Research Findings
- 事实与约束:
  - blocks 接口只需 accessToken + operatorId + dentryUuid,不需要 spaceId/workspaceId → 同步单篇文档技术上零障碍。
  - `types.DataSourceConfig.ResourceIDs []string`(internal/types/datasource.go:226)是自由字符串数组,可扩展新格式(如 `doc/<dentryUuid>`),后端 `parseResourceID`(connector.go:424)按 `/` 拆 workspace/node,需新增 bare-doc 分支。
  - 前端 `connectorDefs` 硬编码于 DataSourceEditorDialog.vue(:640 dingtalk 定义),资源树由 `loadResources()`(:841)驱动;新增入口需改该组件。
  - wikiNode 有 modifiedTime,而 bare doc 无节点元数据来源:blocks 响应不含修改时间 → 增量判定需新方案(待 Q2)。
  - 文档 URL 形态(用户提供实测样本):个人/一般文档为 `https://docs.dingtalk.com/i/nodes/{dentryUuid}`;带参数表格文档为 `https://docs.dingtalk.com/i/nodes/{uuid}?iframeQuery=entrance%3Ddata%26sheetId%3D...`(query 整串忽略,解析器取 `/nodes/` 后至 `?` 为止);知识库节点为 `https://alidocs.dingtalk.com/i/nodes/{dentryUuid}?utm_scene=...`。两域名共享 `/i/nodes/{uuid}` 路径;现有 `dentryUUIDFromURL`(connector.go:451)只匹配 `/nodes/` 标记不检查域名,全部通吃。
  - 现有同步框架:FetchStream 流式 + Emit 即时入库 + Checkpoint 断点;bare doc 可自然走同一路径(每篇一个 item)。
- 现状链路: walk → listAllWorkspaces 建 workspace→root 索引 → walkTree 深搜 → emitDocument(queryBlocks + blocksToMarkdown)。bare doc 需要绕过 workspace 索引直接 emitDocument。
- 风险与不确定项:
  - 无 modifiedTime → 增量只能"重拉+比对"或"每次全量重建"(Q2)。
  - 删除检测:blocks 404 是否稳定可判删(Q3)。
  - 操作员权限:与 wiki 相同,操作员看不到的文档 403(已有先例,不算新风险,但 bare-doc 403 应在 UI 可见)。
  - URL 粘贴形态多样(短链、复制链接带 query),解析需宽容(Q4)。

- [x] Q3 删除语义:**已决议 A**——blocks 404 → emit IsDeleted(跟随数据源 `sync_deletions` 开关);403/其他错误 → 保留文档、计 failed 并写入同步日志;若实测钉钉对已删文档不返回 404,降级为"永不判删+报 failed",待真实删除实验校准。

## 3. Innovate (Optional: Options & Decision)
### Option A(入口形态,已在 Q1 决议)
- 现有钉钉数据源编辑器内加"按链接添加"输入框,与知识库树选择混存于 `resource_ids`(新格式 `doc:<dentryUuid>`)。
- Pros: 一个数据源统一管理;复用同步调度/日志/自动标签;改动集中。Cons: 资源树 UI 增加一块交互。
### Option B(独立连接器类型 dingtalk_doc)
- Pros: 逻辑隔离。Cons: 用户需维护两个数据源、重复填凭证;注册表/前端/i18n 全量过一遍,性价比低。
### Option C(添加知识条目处粘 URL 一次性抓取)
- Pros: 最快。Cons: 无持续同步/删除联动,不满足"同步"需求。
### Decision
- Selected: A(Q1 用户确认,并提供真实 URL 样本)。
- Why: 复用现有数据源体系全部能力,改动面最小。
### Skip
- Skipped: false
- Reason: 入口形态存在三个实质分叉,已比较。

附带设计(随 Q2/Q3 决议演化):
- 删除统一走"游标差分":`cur.DocHashes` 与 `prev.DocHashes` 对比,消失即 emit IsDeleted(404 判删、取消勾选判删、`sync_deletions` 门控全部收敛到这一条路径,服务层已有门控 datasource_service.go:857)。
- 403/瞬时失败走 `FetchedItem.FetchError`(新增字段),服务层计 `result.Failed++`,不删不更新哈希(下次同步自然重试);该机制同时用于 wiki 文档拉取失败可见性(修复"403 却显示成功"的旧问题)。
- 标题来源:bare doc 无节点元数据,取渲染后第一个 heading 块文本,退化用 `钉钉文档 <uuid前8位>`。

## 4. Plan (Contract)
### 4.1 File Changes
- `internal/types/datasource.go`: `FetchedItem` 新增 `FetchError string`(`json:"fetch_error,omitempty"`)。
- `internal/application/service/datasource_service.go`: `applyFetchedItem` 顶部处理 `FetchError != ""` → 记日志 + `result.Failed++` + return(不入库)。
- `internal/datasource/connector/dingtalk/types.go`: `ddCursor` 新增 `DocHashes map[string]string`(`json:"doc_hashes"`);`newCursor`/`decodeCursor` 初始化与保留。
- `internal/datasource/connector/dingtalk/client.go`: 非 2xx 错误改为带状态码的类型化错误 `apiStatusError{status, body}`(保留现有文案格式),供 404/403 判别。
- `internal/datasource/connector/dingtalk/connector.go`:
  - `makeBareDocID(uuid)` / `bareDocID(rid)`(前缀 `doc:`,冒号与 workspaceID 字符集无冲突);
  - `walk()` 循环头部识别 `doc:` 资源 → `syncBareDoc`;
  - `syncBareDoc`:queryBlocks → blocksToMarkdown → SHA-256;`incremental && prev hash == new hash` → 跳过(仅日志);404 → 不写入 cur 哈希(交给删除差分);其他错误 → emit FetchError 条目 + 继承 prev 哈希;
  - `walk()` 删除差分段新增 `DocHashes` 对比(prev 有、cur 无 → emit IsDeleted);
  - `emitDocument` 失败分支(wiki 路径)从"仅警告"改为 emit FetchError 条目;
  - bare doc 标题:渲染块中第一个 heading 文本,否则 `钉钉文档 <uuid[:8]>`。
- `frontend/src/views/knowledge/settings/DataSourceEditorDialog.vue`: dingtalk 连接器的资源选择区新增"按链接添加文档"输入框 + 已添加文档 chips(可删除、去重);解析规则与后端一致(`/i/nodes/{uuid}`,域名限 `*.dingtalk.com`,query 忽略);存入 `config.resource_ids`(`doc:<uuid>`);编辑回显拆分。
- `frontend/src/i18n/locales/{zh-CN,en-US,ko-KR,ru-RU}.ts`: 新增 `datasource.*` 相关键。
