## 1. Requirements (Context)

- **Goal**:
  在 WeKnora 数据源框架中新增钉钉文档连接器，用户在知识库设置中选择「钉钉」并填写 `AppKey` / `AppSecret` / `操作人手机号` 后，可以把该操作人可见的钉钉知识库（Wiki）中的在线文档同步为 WeKnora 知识库文档，并支持定时增量同步。

- **In-Scope**:
  - 后端连接器包 `internal/datasource/connector/dingtalk/`，实现 `datasource.Connector` 接口（`Validate` / `ListResources` / `ResolveResourceAncestors` / `FetchAll` / `FetchIncremental`）与可选的 `datasource.StreamingConnector`（`FetchStream`）。
  - 鉴权：`appKey` + `appSecret` 换取 accessToken 并缓存；**用操作人手机号在连接器内部解析 unionId**（手机号 → userid → unionId），用户无需手填 unionId。
  - 资源列举：列出企业/操作人可见的钉钉知识库（workspaces）；按父节点懒加载知识库目录树。
  - 内容获取：`category = ALIDOC` 的在线文档，通过「查询块元素」接口读取块元素树，转换为 Markdown 后作为 `FetchedItem` 落库。
  - 同步模式：全量、增量（按 `modifiedTime` 与游标比对）、流式（边拉边 ing++ 检查点，支持中断续传）。
  - 容器注册：`initConnectorRegistry` 注册该连接器，使 `/datasource/types` 中已有的 `dingtalk` 条目从「挂名」变为可用。
  - 前端：在数据源类型卡片中加入「钉钉」，提供三个配置字段与表单校验；补充图标与 i18n 文案。
  - 单元测试：块元素 → Markdown 渲染、游标编解码。

- **Out-of-Scope**:
  - 钉盘 / 云盘（Drive）连接器（用户明确「云盘就不用」）。
  - 知识库中**上传的普通文件**（非 ALIDOC，如 docx/pdf）的下载与同步：v1 跳过并记录元数据与日志（见 §3 决策与 §2.1 Q4）。
  - 钉钉侧的写操作（新建/删除知识库、写入文档、上传文件）。
  - 事件订阅（`storage/events/subscribe`）驱动的推送式增量：v1 采用轮询，推送列为后续优化项。
  - 钉钉知识库小组/权限等管理类接口。
  - IM 侧（钉钉机器人）已有功能不做改动。

- **Acceptance Criteria**:
  - [ ] AC1 配置合法的 `app_key` / `app_secret` / `operator_mobile` 后，`Validate`（对应「测试连接」）成功；手机号无效或非在职员工时返回明确错误。
  - [ ] AC2 `ListResources(parentID="")` 返回操作人可见的知识库列表；`ListResources(parentID=<nodeId>)` 返回该节点的子节点（懒加载），`HasChildren` 反映 `hasChildren`。
  - [ ] AC3 全量同步能把所选知识库下 `category=ALIDOC` 的在线文档拉取为 Markdown 内容并交给既有 ingest 管线（文档能在知识库文档列表中出现）。
  - [ ] AC4 增量同步仅对 `modifiedTime` 发生变化的节点重新拉取内容；未变化节点不产生 `FetchedItem`。
  - [ ] AC5 `FetchStream` 在页边界写入检查点；从中断恢复时已同步且未变化的节点被跳过（可重复执行收敛）。
  - [ ] AC6 非 ALIDOC 节点被跳过：不报错、不影响其它文档，且跳过原因记录在日志中。
  - [ ] AC7 连接器注册后，创建 `type=dingtalk` 的数据源不再因「连接器未找到」失败；前端可选择「钉钉」并填写表单、保存后能触发测试连接。
  - [ ] AC8 单元测试覆盖块元素 → Markdown 的主要块类型（段落/标题/引用/列表/表格/高亮块/分栏）与游标编解码，`go test ./internal/datasource/connector/dingtalk/...` 通过。
  - [ ] AC9 `go build ./...` 与前端 `npm run build`（或类型检查）通过，无新增 lint/类型错误。

## 2. Research Findings

### 2.1 钉钉侧事实（已实测确认）

- **授权**：企业内部应用用 `POST https://api.dingtalk.com/v1.0/oauth2/accessToken`（body：`appKey`/`appSecret`）换取 `accessToken`，有效期 7200s，需自行缓存。文档/存储类接口用请求头 `x-acs-dingtalk-access-token` 传递。
- **两套 token**：通讯录老接口（手机号查询、用户详情）走 `https://oapi.dingtalk.com`，把凭证作为 `access_token` 参数；其中 `gettoken` 为旧版入口（官方标注「已升级、不再新增能力」）。新版 accessToken 是否可直接用于 oapi 老接口**未验证**（Q2），实现时按「分别获取、分别缓存」处理更稳妥。
- **主链路接口**：
  - 列知识库：`GET /v2.0/wiki/workspaces`（`operatorId` 必填，`maxResults` ≤ 30，返回 `workspaces[]` 与各自 `rootNodeId`）。
  - 列子节点：`GET /v2.0/wiki/nodes`（`parentNodeId` / `operatorId` 必填，`maxResults` ≤ 50，返回 `nodes[]` + `nextToken`）。
  - 单节点 / 批量节点：`获取节点`、`批量获取节点`。
  - 读在线文档正文：`GET /v1.0/doc/suites/documents/{docKey}/blocks`（可按 `startIndex`/`endIndex`/`blockType` 过滤；**只返回一级块元素**）。
  - 节点字段：`nodeId`（= dentryUuid）、`workspaceId`、`name`、`type`（FILE）、`category`（**ALIDOC** 表示在线文档）、`extension`、`url`、`creatorId`、`modifierId`、`createTime`、`modifiedTime`、`hasChildren`、`statisticalInfo.wordCount`。
- **文档数据结构**：在线文档 = 块元素树。
  - `BlockType` 枚举：`paragraph`、`heading`、`blockquote`、`callout`、`columns`、`orderedList`、`unorderedList`、`table`、`tableRow`、`tableCell`。
  - `InlineType` 枚举：`text`（bold/italic/strike/underline/color/sz/fonts）、`sticker`（emoji）、`image`（`src`）、`link`（`href` + children text）。
  - **块元素 JSON 形状（已确认，来自「插入块元素」/「查询块元素」示例）**：判别式 `blockType` + 同名 key 携带属性 + `id`/`index`：
    ```json
    { "blockType": "paragraph", "paragraph": { "text": "foo" }, "id": "lmoasis2f3wxmwyyyy", "index": 2 }
    ```
    → Go 侧对应「判别式字段 + 各类型可选指针」结构，而非 map 或单字段。
  - 嵌套约束：`callout`/`columns` 的 children 是 `BlockElement`；`paragraph`/`heading`/`orderedList`/`unorderedList`/`blockquote` 的 children 是 `InlineElement`；`table` 可用 `cells: String[][]`（`rolSize`/`colSize`）直接取二维文本。
- **权限（后台需开通并发布版本）**：
  - 必开：`Wiki.Workspace.Read`（知识库读）、`Wiki.Node.Read`（知识库节点读）、`Storage.File.Read`（企业存储文件读，「查询块元素」依赖它）。
  - 手机号解析 unionId 需要：`qyapi_get_member_by_mobile`（根据手机号获取成员基本信息）、`qyapi_get_member`（成员信息读）。
  - 可选（v1 不做文件下载，暂不需要）：`Storage.DownloadInfo.Read`、`Document.WorkspaceDocument.Write`。
- **手机号 → unionId 路径**：`POST oapi.dingtalk.com/topapi/v2/user/getbymobile`（body `mobile`）→ `userid`；再 `POST oapi.dingtalk.com/topapi/v2/user/get`（body `userid`）→ `result.unionid`。**该路径仅支持在职员工**。
- **无导出 API**：钉钉文档板块的服务端接口几乎全为写操作（覆写文档、插入/更新/删除块元素），读取仅「查询块元素」；预览接口 `openInfos/query` 只返回浏览器可打开的 url，不是可下载实体。故在线文档**只能按块读取后自行转 Markdown**。

### 2.2 WeKnora 代码侧接入点（已确认）

- **接口**：`datasource.Connector`（`Type`/`Validate`/`ListResources(ctx,cfg,parentID)`/`ResolveResourceAncestors`/`FetchAll`/`FetchIncremental`）+ 可选 `datasource.StreamingConnector`（`FetchStream(ctx,cfg,cursor,h)`）。`StreamHandler` 提供 `Emit(item)` 与 `Checkpoint(cursor)`。
- **调度分派**：`DataSourceService.ProcessSync` 会类型断言 `connector.(datasource.StreamingConnector)`，命中则走 `processSyncStreaming`（`internal/application/service/datasource_service.go:670`），否则走 `FetchAll`/`FetchIncremental`（:681/:686）。→ 实现 `FetchStream` 是首选路径。
- **类型常量已存在**：`types.ConnectorTypeDingTalk = "dingtalk"`（`internal/types/datasource.go:34`）；`types.ChannelDingtalk = "dingtalk"`（`internal/types/knowledge.go:32`）。
- **元数据已「挂名」**：`ConnectorMetadataRegistry` 已有 dingtalk 条目（`internal/datasource/connector.go:240`，`AuthType: "api_key"`，`Capabilities: ["incremental"]`，`Priority: 7`），但**无实现、未注册**，`CreateDataSource` 在注册表查不到类型会直接失败（`datasource_service.go:82`）。
- **注册点**：`internal/container/container.go` 的 `initConnectorRegistry()`（:1663），现有注册：feishu/lark wiki、feishu/lark drive、notion、yuque、ima、rss、gitlab。
- **配置结构**：`types.DataSourceConfig{ Type, Credentials map[string]any, ResourceIDs []string, Settings map[string]any, MultimodalEnabled bool }`；凭证以 JSON 序列化存于加密 `Config`，`StripNonSecretCredentials(connectorType)` 负责剥离非密文字段（`internal/types/datasource.go:218/269`）。
- **FetchedItem**：`ExternalID/Title/Content([]byte)/ContentType/FileName/URL/UpdatedAt/Metadata(map[string]string)/IsDeleted/SourceResourceID`（+ `ReplacesSubtree`）。
- **游标**：`types.SyncCursor{ LastSyncTime, ConnectorCursor map[string]any, LastSchemaHash }`。
- **自动打标**：数据源同步会 `resolveAutoTagIDs` 以数据源名创建标签并挂到同步文档（`datasource_service.go:802`），连接器无需额外处理。
- **共享 HTTP 助手**：`datasource.NewConnectorHTTPClient(timeout)`、`datasource.ValidateConnectorBaseURL(raw)`、`datasource.ErrInvalidConfig` / `ErrInvalidCredentials`（`internal/datasource/httpclient.go`、`errors.go`）。
- **可复用模板**：语雀连接器（`internal/datasource/connector/yuque/`，约 2000 行，flat 列表 + `BookDocTimes` 游标 + 限流让步 + 失败占位项）最接近；飞书 docx 的块渲染（`internal/datasource/connector/feishu/core/markdown.go:26 blocksToMarkdown`，320 行，覆盖 14 种块）是块 → Markdown 的直接参照。
- **前端为硬编码列表**：`frontend/src/views/knowledge/settings/DataSourceEditorDialog.vue` 的 `connectorDefs`（:499 起，`ConnectorDef{type,available,docUrl,permissionDocUrl,permissionPageUrl,requiredPermissions,fields[]}`）**不是**由 `/datasource/types` 驱动；新增类型需改此文件。图标映射在 `datasourceIcons.ts`；字段文案在 `frontend/src/i18n/locales/{zh-CN,en-US,ko-KR,ru-RU}.ts` 的 `datasource.field.*`。

### 2.3 风险与不确定项

- **R1（中）嵌套块返回形态**：官方明确「查询块元素」只返回**一级**块元素，但未说明 `tableRow`/`tableCell`、`callout` 内部 `BlockElement` 是以平铺还是需递归再次请求的方式返回。**块元素的 JSON 判别式形状已确认（见 §2.1）**，剩余不确定点仅在嵌套子块的返回形态；渲染器需同时兼容「一级块内已含子块」与「table 走 `cells` 二维数组」两种情形。
- **R2（中）两套 token 兼容性**：新版 accessToken 能否用于 `oapi.dingtalk.com` 老接口未验证；实现按「分别获取」保证正确性，若实测可复用再简化。
- **R3（低-中）图片资源鉴权**：行内 `image.src` 是否为需鉴权的临时地址、是否过期未验证。v1 先原样输出 `![alt](src)`，失败不影响文本内容（Q3）。
- **R4（中）同步规模与限流**：单个知识库可能含大量节点，且钉钉对各接口有频率限制。需按节点逐个（或小批量）拉取并做请求间让步 + 重试（参照语雀 300ms 让步）。
- **R5（低）操作人权限范围**：以个人手机号作为 operatorId，同步范围受限于该员工在钉钉侧的可见权限；若离职或权限回收会导致同步失败（用户已知悉，先按个人账号跑通）。
- **R6（低）前端 i18n 多语言**：四个 locale 文件都需补 key，遗漏会导致其它语言下显示 key 名。

## 3. Innovate (Optional: Options & Decision)

### Option A（推荐）：流式同步 + 块解析 + v1 跳过普通文件
- Pros: `FetchStream` 命中既有流式分派路径，大知识库内存可控、支持检查点续传；块解析是在线文档唯一可行读法；权限需求最小（不碰官方文档自相矛盾的下载写权限）；与飞书/语雀模板同构，风险最低。
- Cons: 非 ALIDOC 的上传文件不同步；增量靠轮询而非事件推送。

### Option B：仅实现 `FetchAll` / `FetchIncremental`（不做流式）
- Pros: 实现量略小。
- Cons: 全量结果需一次性驻留内存，大知识库有 OOM 与超时丢进度风险；放弃既有流式分派与检查点能力。

### Option C：A + 同步知识库内普通文件（docx/pdf）
- Pros: 覆盖面更全。
- Cons: 需额外权限，且官方「知识库下载文件」页标注要求**写**权限、权限列表页标注 `Storage.DownloadInfo.Read`，二者矛盾需实测；会把「钉盘/云盘」相关面引入，超出用户「云盘不用」的边界。

### Decision
- Selected: **Option A**
- Why: 在满足「只做钉钉文档、不做云盘」的前提下，覆盖度与工程稳健性最好；普通文件同步依赖的权限存在官方矛盾且属用户已排除的云盘相关面，推迟到后续版本（对应 Out-of-Scope 与 Q4）。
- Rejected: Option B（内存/续传风险）；Option C（越界 + 权限不确定）。

### Skip (for small/simple tasks)
- Skipped: false
- Reason: 本任务为跨前后端的中等规模改动，需要方案对比。
