## 一、方案总览

### 1.1 一句话定位

**把散落在文档、群聊、个人电脑里的企业知识，变成可检索、可推理、可观测的公司资产。**

三个案例面向三类角色，同源于一个私有化部署的知识中枢平台：

| 案例 | 面向角色 | 锚定痛点 | 核心能力组合 | 自研含量 |
|------|---------|---------|-------------|---------|
| 案例一：研发知识中枢 + AI 编码助手 | 开发 | 排障经验不沉淀、重复问题耗时、新人上手慢 | RAG 知识库 + **自研 MCP Server** 接入 Claude Code/Codex | ★★（已完成） |
| 案例二：产品决策资产库 | 产品 | 文档找不到、历史决策失忆、评审翻旧账 | Wiki 自动蒸馏 + 知识图谱 + 引用问答 | ★（配置为主） |
| 案例三：钉钉企业知识资产中枢 | 管理层 | 知识随人员流失、沉淀不可见、投入重复 | **自研钉钉数据源连接器** + 钉钉 IM 机器人 + Langfuse 观测 | ★★★（本次自研主打） |

> **贯穿主线：部门空间隔离（Workspace RBAC）**--企业落地第一道门是"谁能看什么"。三个案例共享同一套"部门 → 空间 → 角色"权限矩阵（见 §1.5）：不同部门不同空间、空间间文档默认隔离、角色决定读写、AI 调用也不能越权、一切操作留痕审计。这是管理层评委最关心的"能不能在企业真用起来"的答案。

### 1.2 平台底座：为什么选 WeKnora

- **开源可私有化**（Tencent 开源，MIT 协议）：全部文档、向量、会话数据落在公司自己的服务器/Docker 卷，**数据主权完整**，不存在知识外泄给第三方 SaaS 的问题
- **企业级能力完整**：多工作区 RBAC 权限、审计日志、scoped API Key、Langfuse 全链路观测、任务队列治理——这些"管理动作"正是管理层评委关心的
- **模块化可扩展**：LLM、向量库、存储、数据源全部可插拔；Connector 框架官方预留了钉钉接口位（`ConnectorTypeDingTalk` 常量与元数据已存在，实现空缺），我们的自研连接器正好补上
- **国内生态适配**：原生支持钉钉/企业微信/飞书 IM、DeepSeek/Qwen 等国产模型、常见 10+ 文档格式

### 1.3 统一技术约束与选型

| 项 | 决策 | 说明 |
|----|------|------|
| 部署形态 | 本地 Docker Compose 全套（app/frontend/postgres/redis/docreader/mcp-server/Langfuse 栈） | 现场演示零外部依赖（除 LLM API） |
| LLM 推理 | 云端 API（DeepSeek/Qwen）为主，手机热点兜底，可随时切换 Ollama 本地模型 | 文档与知识资产全在本地，**只有推理走云**；模块化设计切换只改配置 |
| 演示数据 | 虚构公司"云梭科技"完整文档集（见 §2） | 无合规风险，剧情可控，可预生成预热 |
| 演示时长 | 每案例 5 分钟，共 15 分钟 + 3 分钟 Q&A | 分镜脚本见配套文档 |

### 1.4 虚构演示数据集设定

虚构一家 **"云梭科技"**——约 200 人的 SaaS 软件公司（做企业协作工具），三个案例共用这一套世界观：

```
云梭科技文档集（约 60-80 篇，全部虚构）
├── 研发线（案例一用）
│   ├── ADR 架构决策记录 ×12（如"ADR-007 订单服务为何从单体拆出"）
│   ├── API 文档 ×8、部署运维手册 ×6
│   ├── 排障手册 ×15（如"网关 502 排查 SOP"、"支付回调重复消费处理"）
│   └── 值班复盘 ×10（含真实感的"踩坑-定位-修复"三段式）
├── 产品线（案例二用）
│   ├── PRD ×15（V1.0-V3.0 三个大版本，含被砍掉的需求）
│   ├── 评审会议纪要 ×12（含"为什么砍掉离线模式"的决策过程）
│   ├── 用户反馈池 ×10、竞品分析 ×5
│   └── 版本发布记录 ×6
└── 全员（案例三用）
    ├── 公司制度/FAQ（报销、入职、IT 服务台）
    ├── 项目周报 ×20、双月 OKR 复盘 ×4
    └── 部门知识文档 ×15（散落在钉钉各群/个人电脑的设定）
```

数据集制作要点：
- 故意埋入**跨文档关联**（如某个 ADR 引用某次复盘、某份 PRD 提到被砍需求）——让知识图谱和 Wiki 蒸馏有戏剧性产出
- 故意埋入**"只有老员工才知道"的暗知识**（如"测试环境订单库每周日会重置"）——让案例三的"知识资产不随人流失"叙事落地
- 提前完成解析、向量化、Wiki 生成，现场只演示增量环节

### 1.5 部门空间权限模型（贯穿三案例的主线）

> 企业知识平台的第一道门不是"AI 多聪明"，而是"谁能看什么"。WeKnora 内置空间级 RBAC，我们把它设计成"部门 -> 空间 -> 角色"三层映射，作为三个案例共同的权限底座。

**空间划分（演示环境中即"云梭科技"的组织结构）：**

| 工作区（空间） | 对应部门/角色 | 成员角色设定 | 隔离效果 |
|---------------|--------------|-------------|---------|
| 研发中心 | 后端/前端/测试 | 架构师=Owner，TL=Admin，工程师=Contributor，新人与外包=Viewer | ADR、排障手册只在本空间可见 |
| 产品部 | 产品经理 | 产品总监=Owner，PM=Contributor | PRD、评审纪要、用户反馈只在本空间可见 |
| 全员知识库 | 行政/HR/IT + 全体员工 | IT 管理员=Owner/Admin，部门接口人=Contributor，全员=Viewer | 制度/FAQ/周报全员可读，仅接口人可写 |
| （可选）共享空间 | 跨部门协作 | 管理员/编辑者/只读 | 把"研发公开 API 文档"以只读方式共享给产品部--横向协作通道，不破坏纵向隔离 |

**四层角色矩阵（平台内置，非自研）：**

```
viewer < contributor < admin < owner
只读提问   上传维护自己的    空间内任意资源    Admin + 删除空间
           KB/Agent         + 管理成员
```

**资源归属守卫（关键机制）：** 每个知识库/Agent 记录 `creator_id`，子资源（文档、chunk、FAQ、Wiki 页面）沿归属链回溯--**"Contributor 在自己的 KB 里像 Owner，在别人的 KB 里像 Viewer"**。两个 TL 都是 Admin，但 A 部门的 TL 动不了 B 部门 Contributor 上传的知识库。

**纵深防御四道闸口（管理层话术，全部平台内置）：**

1. **空间隔离**：不同部门不同空间，知识库默认不出空间；跨部门要走共享空间（且共享不能绕过源空间 RBAC）
2. **角色 + 归属双重校验**：角色不够看不了，角色够了但不是你的资源也写不了
3. **AI 调用同样受限**：MCP/API Key 的每次检索都带着身份和空间上下文--钉钉群机器人、AI 编码助手检索到的永远只是"提问者有权看的知识"，不存在"AI 越权泄密"
4. **全量审计**：`audit_logs` 记录成员变更、角色调整、越权尝试（`rbac.access_denied`）；Langfuse trace 携带 TenantRole，被拒绝的请求在链路里直接可见"谁、什么角色、想干什么、被拒"

**配套治理配置：** `invite_only` 注册模式（新成员必须被邀请进空间）、审计日志 90 天保留、跨空间超管开关默认关闭。

## 二、案例一 · 研发知识中枢 + AI 编码助手（有利于开发）

### 2.1 痛点陈述（评委共鸣点）

1. **排障经验不沉淀**：线上问题解决后，排查思路留在群聊和个人脑子里，下次别人踩同样的坑还要从头再来
2. **重复问题耗时**：新人反复问老员工"这个服务怎么起""这个报错什么意思"，老员工被打断成本高
3. **AI 编码工具不"懂"公司**：GitHub Copilot/Claude Code 很强，但它们不知道公司内部的服务架构、历史决策和踩坑记录，生成的代码经常"不符合我们的规矩"
4. **AI 助手不能有特权**：让 AI 检索内部知识，第一担心就是"它会不会把核心 ADR 泄露给外包/新人"--AI 调用必须与人的权限一致，不能成为旁路


### 2.2 方案设计

```
ADR/排障手册/值班复盘/API 文档
        │ 上传导入（PDF/Word/Markdown）
        ▼
   WeKnora 知识库（三级分块 + BM25/向量混合检索 + rerank）
        ▲
        │ 自研 MCP Server（8082 端口，stdio/SSE/HTTP 三传输 + Bearer 鉴权）
Claude Code / Codex / OpenCode 等 AI 编码工具
        │
        ▼
开发者提问："这个报错上周谁处理过？"
AI 自动检索知识库 → 带引用回答 → 直接给出修复建议
```

- **自研 MCP Server 已完成并接入三个 AI 编码工具**（Claude Code / Codex / OpenCode），提供文档检索、知识问答、知识条目管理等 MCP 工具
- 开发者在 IDE/终端里自然语言提问，AI 助手**先查公司知识库再回答**，答案附引用来源（点开能看到原始复盘文档）
- **权限一致性（本案例的信任基石）**：MCP Server 背后是 scoped API Key，检索范围被限制在"发起者所在空间、有权访问的知识库"--AI 编码助手检索到的永远是"提问的这位工程师有权看的知识"。新人/外包（Viewer）问"核心支付网关的架构决策"，AI 不会越权吐出 Admin 才可见的 ADR
- Langfuse 记录每次检索与推理链路：哪些问题被问了、命中了什么知识——这就是"知识使用度"数据的来源

### 2.3 演示要点（详见演示脚本）

1. 终端里 Claude Code 直接回答"云梭科技网关 502 上次怎么解决的"，**答案带引用，可点开溯源**
2. 对比：关闭知识库工具后同一个问题 AI 答非所问（证明知识库的价值，不是模型的价值）
3. **越权即拒**：切到 Viewer 身份（新人员工账号）再问"支付网关核心架构决策"，AI 检索不到/明确告知无权限--AI 与人同权，无旁路
4. Langfuse 后台展示调用链路，trace 里可见提问者 TenantRole（给技术加分项）

### 2.4 收益叙事（管理层话术）

- 老员工被打断次数下降：重复问题由 AI 首答，人只处理 AI 答不了的
- 新人上手周期缩短：环境、规范、历史坑位一问便知
- 排障 SOP 复用：一次沉淀，全组受益；Langfuse 数据可以看到"知识被调用"而非"文档在吃灰"

## 三、案例二 · 产品决策资产库 + Wiki 自动蒸馏（有利于产品）

### 3.1 痛点陈述

1. **历史决策失忆**："这个功能当初为什么这么做？"——要翻三个月前的群聊、问三个当事人
2. **文档找不到**：PRD 散落各处，评审时"我记得有份分析"但找不到
3. **新人产品经理接手旧功能如考古**：没有结构化的来龙去脉
4. **敏感内容不该人人都见**：未发布的功能规划、定价策略、裁撤讨论--散在共享盘里人人可看，出事就是合规事故

### 3.2 方案设计

```
两年份 PRD + 评审纪要 + 用户反馈 + 竞品分析
        │ 批量导入
        ▼
   WeKnora 文档知识库
        │ Wiki 模式（Agent 自动蒸馏）
        ▼
   结构化产品 Wiki（互联 Markdown 页面 + 知识图谱）
        │
        ├── 图谱可视化：功能模块 ↔ 决策 ↔ 用户反馈 的关系网
        └── 引用问答："离线模式当初为什么砍掉？" → 引用评审纪要原文
```

- 用 WeKnora **Wiki 模式**把 50 份散乱文档自动蒸馏成结构化、互链的产品知识库（如"消息同步模块"页面自动链接相关 ADR、评审记录、用户反馈）
- **知识图谱**直观展示产品决策网络——这是现场最抓眼球的画面
- 评审会前：Agent 一键检索"这个需求历史上讨论过什么"，带出处
- **空间隔离下的蒸馏**：整个蒸馏发生在"产品部"空间内部；涉密 PRD（如未发布定价策略）放独立知识库并收紧归属，Wiki 与图谱只索引该空间内有权的知识库。研发想看"消息模块的对外 API 约定"？通过**共享空间**以只读方式把"API 文档库"共享给研发空间--横向协作走共享通道，纵向上产品部的裁撤讨论、定价策略依然只有产品部可见

### 3.3 演示要点

1. 一键触发 Wiki 生成（预生成 + 现场增量，避免干等）→ 展示生成的互链页面
2. 知识图谱展开动画，点开"离线模式"节点看到关联的评审纪要与用户反馈
3. 提问"V2.0 为什么砍掉离线模式"，回答引用会议纪要原文（**决策可溯源**）
4. **跨部门隔离对照**：切到研发空间账号，产品 Wiki 不在其列表中；打开共享给研发的"API 文档库"（只读）--共享通道给该给的，隔离墙挡住不该见的

### 3.4 收益叙事

- 决策有据：任何产品决策 30 秒溯源到当时的讨论记录
- 资产复用：两年的文档变成可推理的知识网络，而非死档案
- 评审提效：会前自动检索历史讨论，减少重复争论

## 四、案例三 · 钉钉企业知识资产中枢（有利于老板 · 自研主打）

### 4.1 痛点陈述（管理层视角）

1. **知识随人流失**：核心文档在离职员工的钉钉空间和个人电脑里，人走知识走
2. **沉淀不可见**：公司到底积累了什么知识资产？没人说得清，也没法度量
3. **员工获取知识路径长**：文档在钉钉文档/群文件/本地各处，找东西靠熟人

> 我们公司的协作主平台就是钉钉——这个案例与公司现实直接挂钩。

### 4.2 方案设计（全链路闭环）

```
钉钉知识库/企业文档                员工在钉钉群 @知识机器人
        │                                  │
        │ ① 自研钉钉数据源连接器            │ ③ 内置钉钉 IM 机器人（Stream 模式）
        │   （补齐框架预留的空缺）           │   （websocket 长连接，无需公网回调）
        ▼                                  ▼
     WeKnora 知识中枢 ──────────→ RAG 问答（带引用来源）
        │
        │ ② Wiki 化沉淀 + RBAC 权限 + 审计日志
        ▼
     Langfuse 观测：知识使用热度、问答质量、token 成本
        │
        ▼
     管理层仪表盘：公司知识资产"活"了，看得见、可度量
```

三个环节：

1. **自研钉钉数据源连接器（本方案的自研核心）**
   - WeKnora Connector 框架预留了 `ConnectorTypeDingTalk` 类型与元数据注册，但官方未实现——我们按 Connector 接口规范（Validate / ListResources / FetchAll / FetchIncremental）实现钉钉版
   - MVP 范围（2 周内）：钉钉知识库文档列表 + 文档内容拉取 + 全量同步 + 手动触发
   - 加分项（时间允许）：基于修改时间的增量同步、钉钉组织内多空间选择
   - 凭证方案：自建钉钉测试组织，注册企业内部应用申请文档权限，完全可控

2. **钉钉 IM 机器人问答（内置能力，零开发）**
   - WeKnora 原生支持钉钉机器人（Stream/websocket 模式，现场用手机热点即可跑通，无需内网穿透）
   - 员工在群里 @机器人 提问，答案带引用出处，把"问熟人"变成"问机器人"
   - **机器人的答案也守规矩**：每个 IM 渠道绑定一个工作区，群机器人检索的只是该空间内有权的知识库。财务群机器人答不了研发 ADR，研发群机器人看不见薪酬制度--**"在哪个群，就只能问哪个群的知识"**，这是企业敢把 AI 放进群聊的前提

3. **可观测管理层仪表盘**
   - Langfuse + WeKnora 任务队列/审计能力：哪些知识被问得最多、哪些文档从没被用过、token 成本多少
   - 给老板的画面："公司知识资产的活跃度热力图"

### 4.3 演示要点

1. 钉钉后台新建一篇文档（现场真实操作）→ 触发同步 → 文档出现在 WeKnora 知识库（**自动同步，无需人工搬运**）
2. 钉钉群里 @机器人："新员工入职报销流程是什么？" → 带引用回答（**员工零门槛使用**）
3. Langfuse 仪表盘展示问答量、热门知识、成本（**知识资产可度量**）
4. 收尾一页：全部数据在公司自己服务器上（**数据主权**）
5. **权限压轴戏**：切到"全员知识库"空间成员管理页，展示四类角色成员清单 -> 打开审计日志，指给评委看 `rbac.access_denied` 越权拦截记录 + Langfuse trace 里的 TenantRole（**"谁来过、谁被拦了，全有记录"**）

### 4.4 收益叙事（老板话术）

- **知识资产归公司**：钉钉文档自动沉淀进公司知识中枢，人走了知识留下
- **员工提效零门槛**：不装新 App、不改习惯，在天天用的钉钉里 @机器人 就行
- **投入可度量**：Langfuse 看板直接呈现使用量与价值，AI 投入不再是黑盒
- **数据主权**：私有化部署，公司知识不出内网（推理层可切换本地 Ollama 模型，实现全离线）
- **权限隔离兜底**：部门空间天然隔离，AI 机器人同人同权、无越权旁路，越权尝试全量审计--"敢用"和"好用"同样重要

### 4.5 风险与降级路径

| 风险 | 概率 | 降级方案 |
|------|------|---------|
| 钉钉连接器 2 周内做不完 | 中 | 降级为"钉钉文档手动导出 → WeKnora 批量导入 + IM 机器人问答"（IM 是内置能力，保住闭环演示） |
| 钉钉 API 权限/审核卡住 | 低（自建测试组织） | 提前 3 天完成凭证验证；最坏情况录制同步过程视频备用 |
| 现场 LLM API 不可用 | 低 | 手机热点兜底；预置 Ollama 小模型配置可 5 分钟切换 |
| Wiki 生成现场太慢 | 中 | 全部预生成，现场只演示增量文档的同步与问答 |

## 五、整体叙事线（比赛主线）

**开场**：知识在哪里？——在钉钉、在群聊、在离职员工的电脑里。知识没变成资产，是因为它不可检索、不可推理、不可度量。

**展开**：三个角色、三个场景、同一个平台——
- 开发：AI 编码助手"懂公司"（自研 MCP 已落地）
- 产品：决策资产库 + 知识图谱（配置即用）
- 管理：钉钉知识中枢，知识资产看得见（自研连接器补齐生态）

**收尾**：技术上"开源底座 + 自研扩展"（MCP Server 已完成 + 钉钉连接器进行中），商业上"私有化、可度量、零门槛"。这不是 PPT 项目，是已经跑起来的系统。

**暗线贯穿**：部门空间隔离与 RBAC 权限矩阵--案例一的"AI 同权无旁路"、案例二的"共享通道 + 隔离墙"、案例三的"机器人按群守规 + 全量审计"。企业级不是功能多，而是"谁能看什么"这件事有工程答案。
